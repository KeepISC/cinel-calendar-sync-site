Privacy Policy

Last updated: 10 October 2026

CINEL Calendar Sync is a Python application that automatically retrieves training schedules from the CINEL platform and synchronizes them with a publicly accessible Google Calendar. The calendar is intended primarily for classmates, but anyone with its public link can view its events. This policy describes data handling by the script, whether it runs locally or automatically through GitHub Actions.

The calendar and application are independently maintained by the calendar owner. They are not an official CINEL service.

Data accessed

The application uses the calendar owner's personal CINEL credentials to retrieve training schedules. It uses the owner's Google OAuth authorization to access the Google Calendar API. Its requested Calendar permission permits reading and managing calendar data; the script uses that access to read previously synchronized events and to create, update and delete synchronized schedule events in the configured calendar.

Synchronized events include class dates, start and end times, course/module names and classroom locations. The script also processes event identifiers, descriptions and synchronization metadata to identify and update events.

Classmates and other calendar viewers do not need to authenticate with CINEL or authorize Google OAuth. Viewing the public calendar does not authorize the application to access a viewer's Google account.

How data is used

Google Calendar data is accessed and modified only for schedule synchronization: identify existing CINEL events, compare their details, add missing sessions, update changed sessions, and delete previously synchronized events that no longer appear in the retrieved schedule.

The application does not sell personal information or use Google Calendar data for advertising, profiling or training artificial intelligence models.

Storage and protection

For local execution, CINEL credentials, Google OAuth client credentials and OAuth tokens are stored on the owner's machine. For GitHub Actions execution, credentials and OAuth tokens are stored as protected GitHub Actions secrets and made available to the workflow when it runs. A workflow may materialize these values as files on its runner, including a token file needed by the script.

The owner's CINEL credentials and Google OAuth tokens are kept private, are not shared with classmates or other calendar viewers, and are never intentionally published in calendar events. Access to the public calendar does not provide access to these credentials or tokens.

OAuth tokens allow the script to access Google Calendar and, when supported, refresh its authorization without another browser sign-in. They must be kept private and excluded from public source code and this website.

The script processes retrieved Calendar data in memory during synchronization. Synchronized events remain in Google Calendar until changed or deleted. Console output may include training event titles and synchronization actions; when run in GitHub Actions, this output may be retained in workflow logs under the repository's access and retention settings.

Transmission and sharing

The resulting Google Calendar is publicly accessible. Anyone with the calendar link can view its events, including class dates, start and end times, course/module names and classroom locations. Events may be discoverable more broadly depending on Google Calendar's public-sharing settings. Access is not restricted to classmates.

The script communicates with CINEL to retrieve training schedules and with Google to authorize access and read or modify Calendar events. Training session details are sent to Google as calendar event data.

When the script runs through GitHub Actions, GitHub's runner infrastructure processes credentials, OAuth tokens, training schedules and Google Calendar data as needed to execute the workflow. GitHub may also retain workflow output. Data therefore passes through service providers involved in synchronization; it is not limited to the owner's local device.

Publishing schedule events makes them available to the public; viewers may copy or redistribute them. Google, CINEL and GitHub also handle data within their services according to their own policies.

Your control and retention

The calendar owner controls public sharing and can disable it through Google Calendar's sharing settings, independently of the application's Google OAuth authorization. Disabling public sharing does not remove copies that viewers may already have saved or redistributed.

The owner can stop synchronization by stopping local execution or disabling the GitHub Actions workflow. Google access can be revoked by removing the application's authorization in Google Account settings. Local token and credential files and GitHub Actions secrets can also be removed when they are no longer needed.

Revoking authorization or removing tokens does not delete events already stored in Google Calendar. Those events can be removed separately in Google Calendar. Workflow logs can be managed through GitHub's log deletion and retention controls.

Contact

For privacy questions, support, or questions about data handling or calendar sharing, contact the application administrator.

This website

These pages are static documentation. They contain no application sign-in, forms, analytics scripts or tracking cookies. The website does not receive Google OAuth tokens or Calendar data. GitHub Pages may process ordinary website request information as part of hosting these pages.
